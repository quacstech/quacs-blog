This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

QuACS (quacs.tech) — a Hugo static site for Mateusz Rakowski's QA/quality-engineering blog. Plain HTML/CSS, no JS framework, no build pipeline beyond Hugo itself (no package.json, no go.mod — this is not a Hugo Modules project).

## Commands

- `hugo server` — run the local dev server (drafts are `draft: true`/`draft = false` in front matter and won't render unless `-D` is passed: `hugo server -D`)
- `hugo build` — build the static site into `public/` (gitignored)

There is no test suite, linter, or CI config in this repo.

## Content architecture

Content lives under `content/` in two parallel trees, each with its own layout section:

- `content/articles/<category>/*.md` — case-study articles, grouped into four fixed categories that map 1:1 to `layouts/shortcodes` sidebar menu entries in `hugo.toml` (`quality-assurance`, `processes-and-procedures`, `thoughts`, `ai-in-practice`). Each category directory has its own `_index.md` with a `description` used on the category listing page. Adding a new category means adding both the directory (with `_index.md`) and a `[[menus.sidebar]]` entry in `hugo.toml`.
- `content/digest/digest-YYYY-MM-DD.md` — weekly AI news digests, generated by an external tool (`ai-digest-cli`, credited in the digest footer) and committed as one file per week. These use a flat structure (no subcategories) and `layouts/digest/list.html` redirects `/digest/` to the most recent entry rather than listing all of them.

Front matter conventions (TOML `+++` for `_index.md` files, YAML `---` for articles/digests — both are used, follow whichever a given file already uses):
- `pinned: true` on an article surfaces it in the homepage "pinned" section (`layouts/index.html`); omit or set `false` otherwise.
- `draft: true` hides a page from normal `hugo build`/`hugo server` output.
- `tags` renders as clickable tag pills linking to `/tags/<tag>/` (handled by `layouts/taxonomy/tag.html`).
- Articles may open with the `{{< tldr context="..." issue="..." approach="..." outcome="..." >}}` shortcode (`layouts/shortcodes/tldr.html`) to summarize the case study up front.

## Layout architecture

`layouts/_default/baseof.html` is the shared shell (header/nav/sidebar/footer) that every page renders into via the `main` block. Two things worth knowing:
- Client-side search (both desktop and mobile search boxes) is powered by Fuse.js loaded from a CDN, indexing `layouts/_default/index.json` — a generated JSON index of all regular pages' title/description/content/url/section. Any new page type intended to be searchable just needs to be a `Kind: page`; no manual registration needed.
- A small inline script adds a "copy" button to every `<pre>` block post-render.

Layout resolution follows normal Hugo cascading: `layouts/digest/*` and a hypothetical `layouts/articles/*` would override `layouts/_default/*` for their respective sections; currently only `digest` has section-specific overrides (single/list), everything else (including all article categories) falls back to `layouts/_default/single.html` and `list.html`. `layouts/_default/list.html` itself branches on whether a section has sub-sections (renders a category index) vs. leaf pages (renders an article list) — check this before assuming a new nesting level "just works".
